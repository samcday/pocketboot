# MSM8916 SMP recovery audit, 2026-09-08

This is the historical recovery audit. The pieces were subsequently integrated
and exercised through three consecutive DB410c kexec handoffs; see the
[September 11 implementation and hardware evidence](msm8916-smp-experiments-2026-09-11.md)
for current status and limitations.
The [Samsung A5 validation](a5u-smp-experiments-2026-09-11.md) subsequently
passed the same three-handoff SMP/coherency sequence without UART.

The existing work covers both ends of the intended design: start secondary
CPUs before Pocketboot, use them in Pocketboot, and move them into reserved
parking code before kexec replaces its kernel. The pieces have not yet been
integrated and demonstrated together. This audit made no implementation
changes and performed no hardware boot, flash, or CPU-role operation.

## What is already implemented

The dirty preboot implementation discovers Qualcomm UARTDM through
`/chosen/stdout-path` and aliases; locates Cortex-A53 ACC/SAW register nodes;
programs SCM `BOOT_SET_ADDR_MC`; performs the ACC power/reset sequence; and
rewrites the incoming FDT for spin-table startup. The rewrite disables PSCI,
changes CPU release methods/addresses, and adjusts power-domain and idle-state
properties. A5U and GT510 packaging enables the shim at `0x80008000` with
2 MiB payload alignment. Built preboot binaries and combined kernel images
remain in the old worktree's `target` directory.

Its initial trampoline follows lk2nd's layout: 128 bytes of code, the
big-endian `spin-tab` magic at offset `0x80`, and a shared little-endian
release address at offset `0x88`. The built A5 DTB contains the required
4 KiB reservation, supplied by the dirty kernel DTS.

The kernel prototype introduces `CONFIG_ARM64_SPIN_TABLE_KEXEC` and
spin-table `cpu_disable`, `cpu_die`, and `cpu_kill` operations. It copies
per-CPU parking stubs into reserved memory, clears the old release address,
uses `cpu_install_idmap()` and `cpu_soft_restart()` to reach the stub with
translation/data caching disabled, and acknowledges arrival before waiting
for the next kernel's release. Normal arm64 kexec uses this CPU-hotplug
shutdown path. This design allows secondary CPUs to run normal Pocketboot
work before the handoff.

Current main's A5 configuration does not enable this preboot shim or the
kernel parking feature. Current userspace already has a multithreaded async
executor (`src/runtime.rs`) and concurrent discovery (`src/bootflow.rs`),
so there is existing work that can use the additional CPUs. Performance
benefits still need measurement; online CPUs alone do not prove useful work.

## Gaps to resolve before hardware acceptance

1. **Establish one persistent parking contract.** Preboot, both kernels,
   and the userspace loader must agree on reservation ownership, code,
   release slots, acknowledgements, and lifetime. For the current layout,
   the prototype's CPU1–3 stubs fit at `0x854ff100`, `0x854ff140`, and
   `0x854ff180`. However, the kernel currently assumes spare space after a
   release slot in any containing reserved-memory node. That is not a
   sufficient ownership check. Neither preboot nor a later kernel should
   overwrite a trampoline while another CPU may be executing it. The local
   lk2nd ARM64 path can already start CPUs in this same reservation, so
   preboot must detect/reuse that state or establish safe reset sequencing.

2. **Finish the preboot hardware interfaces.** UART writes currently poll
   TX-ready and write the FIFO without establishing the UARTDM transfer
   mode; U-Boot and lk2nd initialize/use that mode differently. The SMC inline
   assembly marks x2/x3 as input-only even though they are result registers.
   The shim assumes SMC64 instead of probing conventions like U-Boot.
   Secondary startup has a fixed delay rather than an arrival acknowledgement.
   Its FDT rewrite also removes CPU power domains indiscriminately, whereas
   the local U-Boot work was refining that to PSCI domains specifically.

3. **Make kernel parking failures stop handoff.** Stub-installation failure
   is currently only debug-logged while `cpu_die` remains advertised.
   A parking-ack timeout reaches generic hotplug cleanup as a warning,
   allowing shutdown to continue without proving the CPU left outgoing
   memory. Validate support before teardown, and ensure failure after
   teardown cannot proceed into relocation. The park-to-secondary branch
   must also zero x0–x3 as required by the arm64 boot protocol; it currently
   leaves x1–x3 holding its entry and bookkeeping addresses.

4. **Specify and validate cache behavior.** The prototype maintains the
   stub/release/initial-ack ranges, but does not establish a complete
   outgoing-CPU cache-maintenance argument. `cpu_soft_restart()` disables
   translation/caching; it does not itself clean all dirty CPU state. The
   cache-off acknowledgement writes an outgoing-kernel array which the
   primary polls through a normal cached mapping. `READ_ONCE` does not
   establish visibility by itself. These are source-review concerns,
   not observed corruption in a hardware test.

5. **Carry the contract into the target FDT and allocator.** With an
   external target DTB, `src/kexec.rs::with_live_memory()` currently grafts
   only `/memory`. It does not transfer CPU spin-table methods, release
   addresses, the parking reservation, or removal of an unusable PSCI
   description. Existing dirty kexec changes exclude target-DTB reservations
   from placement, which is useful but insufficient when the target DTB
   lacks the live reservation. Both relocation and the incoming kernel's
   memory allocator must preserve the persistent region.

6. **Constrain the initial shutdown scope.** Ordinary offline/online is
   broken in the prototype: `cpu_die` clears the external release slot,
   while `cpu_boot` updates only the internal holding-pen selector.
   Implement re-entry or reject ordinary hotplug while supporting kexec's
   shutdown. CPU0 has no prepared stub, so initially keep CPU0 as the reboot
   CPU. Crash stop and ordinary stop IPIs have different preparation paths;
   this prototype does not establish crash-kexec or general CPU-off support.

The local U-Boot v3 preparation also contains an undeclared `name_len` in
`remove_psci_power_domain()` (`msm8916-smp.c:106`). Use it as a reference with
review, not as an assumed build-ready replacement for the published series.

## Suggested implementation sequence

1. Preserve the dirty/untracked preboot and kernel-DTS work in explicit
   recovery commits. Forward-port onto current Pocketboot so the later
   display and fastboot improvements remain available. Preserve the
   unrelated existing `src/kexec.rs` edits while integrating their relevant
   reservation support. Make the reservation reproducible in the pinned
   build instead of depending on a dirty kernel checkout.
2. Agree the persistent reservation/parking ABI and target-FDT propagation,
   then fix the concrete preboot and kernel issues above. Keep diagnostics
   bounded: previous A5 testing showed verbose synchronous UART logging can
   starve USB.
3. Transiently boot from lk2nd into the integrated Pocketboot image and
   capture preboot stages, actual FDT, kernel identity, four online CPUs,
   and CPU work counters under a concurrent workload. The existing display
   runner expects an already-running Pocketboot device; its initial
   identity gate must not be reused blindly for lk2nd.
4. Kexec to a second Pocketboot image. Require evidence that all three
   secondaries acknowledged reserved-code parking before relocation, then
   that all four CPUs are online and doing work after handoff. Retain the
   native-display and fastboot usability checks.
5. Repeat with a separately supplied destination DTB and multiple handoffs,
   exercise placement near the reservation, and test missing/invalid
   reservation and absent-ack failures. Then boot the intended OS kernel
   through the same contract. A successful first boot or four online CPUs
   in only one kernel is not the completion criterion.
